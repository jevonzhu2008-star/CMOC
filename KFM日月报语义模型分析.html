整体架构清晰：两张事实表分别从 SAP BW 立方体 ZRPP_CP006 的两条查询按月循环取数，映射表的维度属性通过 M 层 Join 物化进事实表，DAX 侧用三个 UDF（动态格式字符串）统一格式化。主要风险集中在硬编码路径、脏数据（前导空格）和若干口径不一致。

模型总览

关键架构特征

  • 无模型关系：model.tmdl 仅有 ref table，无 relationship。维度属性（类别/序号/环节）在 M 查询里 join 后直接物化进事实表，两张事实表完全独立。
  • 动态格式字符串：依赖兼容级别 1702 的 DAX 原生函数（UDF），FormatAmount / FormatRatio 按单位（%/t/t/数量）动态返回格式。
  • 独立值筛选：valueFilterBehavior: independent，配合「无关系」设计，两事实表各自独立筛选。
  • 映射表是数据源而非维度：映射表仅作为 M 查询的 join 源存在，模型内不参与关系/切片。

KFM选冶厂月报（月报事实表）

①连接 SAP BW 立方体 ZRPP_CP006，取查询 Q0002
②按 p_月报起始日期→当年 12 月逐月循环，每轮 Cube.ApplyParameter 传月份 ZMSDQNY，展开 8 个维度列 + 15 个度量列
③各月结果 Table.Combine 合并；添加固定列 矿体="KFM"
④左连接 月报指标映射（键 指标项），补齐 类别/序号/总类别/环节序号；剔除序号为空的未匹配行
⑤派生 类别2（序号 ∈ {5,13,14,15,16} 时按 类别×产品分类 细分铜/钴）、排序（序号×10 + 铜钴次序）
⑥计算 最近月份（实际数非空且≠0 的最大月份）、日期（YYYYMM→当月1日）、月份-筛选器（最近月份→文本「最近月份」）
⑦保留最终 19 列 + 类型转换

L1-KFM日报（日报事实表）

①连接同一立方体，取查询 Q0001；按 p_日报起始日期→当年 12 月逐月取数，展开 9 个维度列 + 4 个度量列
②派生 指标名：约 20 条 if-else 规则，按 指标名称×产品分类×工序 映射为报表口径名（如「出矿品位TCu」「产量-阴极铜」）
③左连接 日报指标映射（键 指标名称），补齐 类别/序号/总类别/环节序号；派生 类别2 与 排序、固定列 地域="KFM"
④日期派生：年、标准日期、上月年月编码
⑤内联两个中间表：全年预算数（从月报按 产品分类×年×指标项 汇总）、累计预测数（从月报按 月份×产品分类×指标项 汇总，经 上月年月编码 join 回来）

映射表

两张映射表结构相同（序号/指标项/类别/环节/环节序号/报表），均从 Excel 指标映射.xlsx 的「日报」「月报」两个 Sheet 读取，仅做 PromoteHeaders + 类型转换。

问题清单

按影响程度分级：严重 会导致刷新失败或数据错误；中等 逻辑可疑或口径不一致；轻微 可维护性问题。

严重映射表数据源路径硬编码为他人机器的绝对路径

日报指标映射.tmdl / 月报指标映射.tmdl — partition source

两张映射表的 M 查询写死 File.Contents("C:\Users\Xieyu\OneDrive - IPowerBI\…\指标映射.xlsx")，指向开发者 Xieyu 的本地目录。

影响 当前用户（朱惊宏）或其他同事刷新时该路径不存在，映射表加载失败 → 事实表的 join 步骤失败 → 整个模型刷新中断。

建议 改为 Power Query 参数或相对路径；更稳妥的是把映射数据作为静态表内联进模型（数据量小、变更不频繁）。

严重日报表「类别2」值带前导空格（脏数据）

L1-KFM日报.tmdl — 添加类别2 步骤

四个映射结果带 1–2 个前导空格：" 铜选冶综合回收率TCu"、" 钴选冶综合回收率TCo"、" 阴极铜产量"、" 氢氧化钴含钴产量"。

影响 前导空格使同一逻辑值出现多个文本形态，导致筛选、分组、排序错乱（疑为用空格做视觉缩进的 hack，但污染了数据）。

建议 去掉前导空格；视觉缩进改用已有的 排序 列或 Text.PadStart 单独生成显示列。

中等模型未定义任何关系

model.tmdl — 仅有 ref table，无 relationship

5 张表之间零关系。这是「扁平化」设计的刻意选择（映射列已物化进事实表），本身可行，但代价是：

影响 跨表筛选不传播；DAX 需手动合并（如 FormatAmount 用 COALESCE 取两表单位）；映射表成为「孤岛」，无法作为独立切片维度。

建议 保留现状需团队明确约定；若未来需要映射表做切片器或统一筛选，需重构为星型关系。

中等月报与日报的「比计划」口径不一致

度量值.tmdl — 月比计划 vs 月比计划L1

月报 月比计划 = DIVIDE([月完成],[月计划])，对 % 单位（品位/回收率等）也直接算比率；日报 月比计划L1 则对 % 单位返回差额（百分点差）。

影响 同类指标在两张表口径不同，报表层若混排会出现「月报显示比率、日报显示差额」的不一致。

建议 明确业务口径并统一；若确实月报要比率、日报要差额，需在文档中注明并避免混用。

中等「年累计完成L1」用「累计预测数」计算「完成」

度量值.tmdl — 年累计完成L1
年累计完成L1 =
VAR A = SUM('L1-KFM日报'[累计预测数])   // 累计预测
VAR B = [月累计]                          // 当月累计实际
RETURN A + B

影响 度量值名为「完成」，却使用「累计预测数」字段。若该字段实为「截至上月累计实际数」（命名误导）则无碍；否则属于逻辑错误。

建议 核实 SAP 累计预测数 的真实口径，必要时重命名字段或改用累计实际数字段。

中等内联中间表用 List.Average 聚合

L1-KFM日报.tmdl — 全年预算表 / 月累计预测表

两个内联中间表在 Table.Group 里用 List.Average 对数值取平均。同一分组若数据完整（12 个月各一条）平均=原值，但一旦出现缺失、重复或异常值，平均值会失真并掩盖问题。

建议 改用 List.Max / List.First（取非空唯一值），并增加数据质量校验。

中等「最近月份」用「实际数 ≠ 0」过滤

KFM选冶厂月报.tmdl — 最近月份 步骤

最近月份 = List.Max(Table.SelectRows(…, each [实际数] <> null and [实际数] <> 0)[月份])。真实产量为 0 的月份会被误判为「无数据」。

影响 「月份-筛选器」的「最近月份」语义错误，SameMonthPriorYear 的同期计算随之错位。

建议 仅排除 null，或引入「数据截止月」参数由业务维护。

中等「标准日期」用 Text.Replace(".0","-") 的脆弱转换

L1-KFM日报.tmdl — 添加标准日期 步骤

标准日期 = Date.From(Text.Replace([日期], ".0", "-"))，依赖 SAP 日期字符串恰好含 .0 子串；而同表的 年 列用 Date.From([日期]) 直接转换（未做替换），两处解析不一致。

建议 统一日期解析，用显式格式（Date.FromText 带 format/culture 参数）。

轻微「指标名」映射为约 20 条 if-else 硬编码

L1-KFM日报.tmdl — 添加指标名 步骤

业务映射规则硬编码在 M 里，可维护性差。建议把映射规则移入「日报指标映射」Excel（新增「指标名」列），M 只做 join。

轻微SAP BW 服务器 IP 硬编码

两个事实表 — SapBusinessWarehouse.Cubes("10.43.13.31", …)

服务器地址硬编码。迁移时需改代码，建议参数化。

合理之处与总结建议

已完成的改进： 3 个 DAX 函数已按功能重命名（FormatKFM→FormatAmount、FormatKFM2→FormatRatio、PriorYearMonthValue→SameMonthPriorYear）；代码注释已按实际逻辑修正（含 FormatRatio 的格式注释）。
值得保留的设计： 兼容级别 1702 + DAX UDF 统一动态格式；「月份-筛选器」用「最近月份」文本标记并由 SameMonthPriorYear 解析，解决了「最近月份」动态语义；排序键「序号×10 + 铜钴次序」；月报起点留出 2025 全年以支持去年同期。

优先处理顺序

1修复映射表路径（严重）——否则换机器/换用户即无法刷新。
2清理类别2 前导空格（严重）——保证筛选与分组正确。
3核实「年累计完成L1」与「比计划」口径（中等）——确认业务语义，避免报表数字错位。
4统一日期解析、List.Average、最近月份过滤（中等）——提升健壮性。
5指标映射规则外置、服务器参数化（轻微）——改善可维护性。

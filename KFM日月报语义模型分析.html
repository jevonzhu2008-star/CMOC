关键架构特征

  • 无模型关系：model.tmdl 仅有 ref table，无 relationship，两张事实表完全独立。
  • 动态格式字符串：兼容级别 1702 的 DAX UDF（FormatAmount / FormatRatio）按单位动态返回格式。
  • 独立值筛选：valueFilterBehavior: independent。
  • 二级指标替代「类别2」：两张事实表按「序号 × 产品分类」在 M 层物化二级指标，DAX 侧据此路由口径（品位/回收率/普通量）。
  • 映射表是数据源而非维度：映射表仅作 M join 源，不参与关系/切片。

新口径度量值（4，displayFolder「01新口径」）

业务口径：入矿品位 = 入磨金属量 ÷ 原矿处理量；选冶回收率 = 加权浸出率 × 加权洗涤效率 × 修正系数（铜 0.995 / 钴 0.98），均 ×100 成百分比数值。

度量值公式

问题清单

按影响程度分级：严重 会导致刷新失败或数据错误；中等 逻辑可疑或口径不一致；轻微 可维护性问题。

严重v_钴回收率_新口径 的 RETURN 返回调试中间变量

度量值.tmdl — v_钴回收率_新口径

度量值末尾 RETURN 返回的是 v_WashRate_MTD（当月洗涤效率），而正确的最终回收率表达式被注释掉了：

RETURN
    // IF(NOT ISBLANK(v_TotalOreCoMetal) && v_TotalOreCoMetal > 0, v_CoFinalRecovery, BLANK())
v_WashRate_MTD

影响 钴回收率度量值返回的是中间量「当月洗涤效率」而非最终回收率，报表数据错误。

建议 取消注释，改回 IF(NOT ISBLANK(v_TotalOreCoMetal) && v_TotalOreCoMetal > 0, v_CoFinalRecovery, BLANK())。

严重年累计完成L1 的 SWITCH 兜底分支仍有 VAR 内联语法错误

度量值.tmdl — 年累计完成L1

SWITCH(TRUE(), …) 的最后一个参数（else）内联了 VAR … RETURN …，DAX 不允许 VAR 出现在函数参数位置：

SWITCH(
    TRUE(),
    SELECTEDVALUE(…) = "原矿钴品位TCo", CALCULATE(…),
    SELECTEDVALUE(…) = "原矿铜品位TCu", CALCULATE(…),
    SELECTEDVALUE(…) = "铜选冶综合回收率TCu", CALCULATE(…),
    SELECTEDVALUE(…) = "钴选冶综合回收率TCo", CALCULATE(…),
    SELECTEDVALUE(…) = "其他指标", BLANK(),
    VAR MonthAccActual = SUM(…)      // ← 非法
    VAR YearToPreMonthAccActual = SUM(…)
    RETURN MonthAccActual + YearToPreMonthAccActual
)

影响 度量值无法通过语义校验，引用它的视觉对象报错。

建议 把 VAR MonthAccActual / YearToPreMonthAccActual 提到 SWITCH 之前，SWITCH 内仅引用变量名。

中等月报「二级指标」与「排序」的序号集合不一致

KFM选冶厂月报.tmdl — 添加二级指标 / 添加排序键

二级指标用 {1004, 1012, 1013, 1014, 1015}，但排序键用 {1005, 1013, 1014, 1015, 1016}（整体 +1），两个集合不匹配。

影响 序号 = 1004 的行不进入排序键分支，铜/钴次序恒为 0，采出品位铜钴无法按序排列。

建议 统一两处序号集合（应同为 {1004, 1012, 1013, 1014, 1015}），或核对映射表实际序号。

中等日报「二级指标」序号 = 2 存在复制粘贴错误

L1-KFM日报.tmdl — 添加二级指标 步骤

序号 = 2 的两个分支条件相同：[产品分类]="全钴TCo" → "出矿品位TCo" 后紧接 [产品分类]="全钴TCo" → "出矿品位TCu"，第二条应为 "全铜TCu"。

影响 序号 = 2 的全铜 TCu 行命中不到「出矿品位TCu」，落到 else [类别]。

建议 第二个分支条件改为 [产品分类]="全铜TCu"。

中等模型未定义任何关系

model.tmdl — 仅有 ref table，无 relationship

扁平化设计的刻意选择，但跨表筛选不传播、映射表成「孤岛」，需团队明确约定；未来若需切片器需重构星型。

中等月报与日报的「比计划」口径不一致

度量值.tmdl — 月比计划 vs 月比计划L1

月报 % 单位算比率，日报 % 单位算差额（百分点差），同类指标两表口径不同。

轻微「指标名」映射为 16 条 if-else 硬编码

L1-KFM日报.tmdl — 添加指标名 步骤

建议把映射规则移入「日报指标映射」Excel（新增「指标名」列），M 只做 join。

轻微新口径度量值命名带草稿标记

度量值.tmdl — 01新口径 显示文件夹

v/v_ 前缀与 _新口径 后缀并存，下划线位置不统一（v钴 vs v_铜），暗示过渡状态。

合理之处与总结建议

已完成的改进：
  • 映射表数据源改 SharePoint.Files，并按 Sheet 名称取数（消除行索引钻取）。
  • SAP BW 服务器/系统编号/客户端ID 参数化，本轮切换至新服务器 10.43.11.32 / 系统 00、新 SharePoint 站点。
  • 「类别2」统一改名「二级指标」，月报序号体系调整为 1004/1012/1013/1014/1015。
  • 月报指标映射补齐「指标类别」列声明（6→7 列）。
  • 「年累计完成L1_v2」并入「年累计完成L1」，删除旧版重复度量值。
  • 回收率改为新口径：矿产品产量 × 浸出率 / CCD 洗涤效率反推，加权后乘修正系数；品位 ×100。
  • 品位/回收率筛选由 ALL 改为 ALLEXCEPT(…[日期筛选器])，保留日期切片。
  • 序号/环节序号/排序 类型统一 int64。
值得保留的设计： 兼容级别 1702 + DAX UDF 动态格式；「月份-筛选器」文本标记 + SameMonthPriorYear 解析；排序键「序号×10 + 铜钴次序」；月报起点留 2025 全年支持去年同期；回收率含修正系数。

优先处理顺序

1修复 v_钴回收率_新口径 RETURN（严重）——取消注释，返回最终回收率而非 v_WashRate_MTD。
2修复 年累计完成L1 SWITCH else 语法错误（严重）——VAR 提到 SWITCH 之前。
3统一月报序号集合（中等）——二级指标与排序键集合应一致。
4修复日报「二级指标」序号=2 复制粘贴（中等）——全铜分支条件改「全铜TCu」。

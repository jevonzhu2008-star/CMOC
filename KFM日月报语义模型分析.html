整体架构清晰：两张事实表分别从 SAP BW 立方体 ZRPP_CP006 的两条查询按月循环取数，映射表的维度属性通过 M 层 Join 物化进事实表，DAX 侧用三个 UDF（动态格式字符串）统一格式化。本轮把「类别2」统一改名为「二级指标」、二级指标细分从「类别」改为「序号」驱动，并精简入选品位体系为 4 个「新口径」度量值（2 个入矿品位 + 2 个选冶回收率）。但当前存在一处严重语法错误（年累计完成L1_v2 的 VAR 内联在函数参数中）需优先修复，另有日报「二级指标」派生的一处复制粘贴错误仍未消除。

关键架构特征

  • 无模型关系：model.tmdl 仅有 ref table，无 relationship。维度属性（类别/序号/环节）在 M 查询里 join 后直接物化进事实表，两张事实表完全独立。
  • 动态格式字符串：依赖兼容级别 1702 的 DAX 原生函数（UDF），FormatAmount / FormatRatio 按单位（%/t/t/数量）动态返回格式。
  • 独立值筛选：valueFilterBehavior: independent，配合「无关系」设计，两事实表各自独立筛选。
  • 映射表是数据源而非维度：映射表仅作为 M 查询的 join 源存在，模型内不参与关系/切片。
  • 二级指标替代「类别2」：两张事实表的二级指标列统一按「序号 × 产品分类」在 M 层物化，DAX 侧据此路由不同口径（品位/回收率/普通量）。

入选品位 / 回收率度量值（4，displayFolder「入选品位」）

业务口径：入矿品位 = 入磨金属量 ÷ 原矿处理量；选冶回收率 = 浸出回收率 × 洗涤回收率 × 修正系数。均取「当月累计 + 上月累计」得年累计，分铜/钴。

度量值公式
v钴入矿品位_新口径DIVIDE(累计入磨金属量[钴], 累计原矿处理量)，VAR 内联 CALCULATE
v铜入矿品位_新口径DIVIDE(累计入磨金属量[铜], 累计原矿处理量)，VAR 内联 CALCULATE
v铜回收率_新口径浸出回收率 × 洗涤回收率 × 0.995；浸出 = (原矿铜金属量 − 浸出渣量×渣铜品位)/原矿铜金属量，洗涤 = (原矿铜金属量 − (CCD7溶液铜金属量 − 尾矿回水铜金属量))/原矿铜金属量
v_钴回收率_新口径同铜回收率公式（钴指标），修正系数 0.98

问题清单

按影响程度分级：严重 会导致刷新失败或数据错误；中等 逻辑可疑或口径不一致；轻微 可维护性问题。历史已修复问题见文末「已完成的改进」。

严重年累计完成L1_v2 的 DAX 语法错误

度量值.tmdl — 年累计完成L1_v2

度量值在 SWITCH(TRUE(), …) 的 else 分支内联了 VAR … RETURN …，且两处 CALCULATE 的第一个参数也内联了 VAR … RETURN …：

SWITCH(
    TRUE(),
    SELECTEDVALUE('L1-KFM日报'[二级指标]) = "原矿钴品位TCo",
    CALCULATE( VAR v_CobaltMetal = … RETURN DIVIDE(…), ALL('L1-KFM日报') ),
    SELECTEDVALUE('L1-KFM日报'[二级指标]) = "原矿铜品位TCu",
    CALCULATE( VAR v_CopperMetal = … RETURN DIVIDE(…), ALL('L1-KFM日报') ),
    VAR MonthAccActual = SUM(…)      // ← 非法：VAR 内联在函数参数位置
    VAR YearToPreMonthAccActual = SUM(…)
    RETURN MonthAccActual + YearToPreMonthAccActual
)

影响 DAX 的 VAR 只能声明在度量值定义顶层、RETURN 之前，不能作为 SWITCH/CALCULATE 的参数内联。该度量值无法通过语义校验，引用它的视觉对象会报错。

建议 把全部 VAR 提到 SWITCH 之前：先声明 MonthAccActual、YearToPreMonthAccActual 及两个品位变量，SWITCH 内仅引用变量名。

中等日报「二级指标」派生存在复制粘贴错误

L1-KFM日报.tmdl — 添加二级指标 步骤

序号 = 2 的两个分支条件完全相同：[序号]=2 and [产品分类]="全钴TCo" → "出矿品位TCo" 后紧接 [序号]=2 and [产品分类]="全钴TCo" → "出矿品位TCu"，第二条的 产品分类 应为 "全铜TCu"。

影响 序号 = 2 的全铜 TCu 行永远命中不到「出矿品位TCu」，落到 else [类别] 分支，日报出矿品位分类错位。

建议 将第二个分支条件改为 [产品分类]="全铜TCu"。

中等模型未定义任何关系

model.tmdl — 仅有 ref table，无 relationship

5 张表之间零关系。这是「扁平化」设计的刻意选择（映射列已物化进事实表），本身可行，但代价是：

影响 跨表筛选不传播；DAX 需手动合并（如 FormatAmount 用 COALESCE 取两表单位）；映射表成为「孤岛」，无法作为独立切片维度。

建议 保留现状需团队明确约定；若未来需要映射表做切片器或统一筛选，需重构为星型关系。

中等月报与日报的「比计划」口径不一致

度量值.tmdl — 月比计划 vs 月比计划L1

月报 月比计划 = DIVIDE([月完成],[月计划])，对 % 单位（品位/回收率等）也直接算比率；日报 月比计划L1 则对 % 单位返回差额（百分点差）。

影响 同类指标在两张表口径不同，报表层若混排会出现「月报显示比率、日报显示差额」的不一致。

建议 明确业务口径并统一；若确实月报要比率、日报要差额，需在文档中注明并避免混用。

轻微新口径度量值命名不规范

度量值.tmdl — 入选品位 显示文件夹

4 个新度量值命名带 v 前缀与 _新口径 后缀（v铜回收率_新口径、v_钴回收率_新口径 下划线位置还不一致），年累计完成L1_v2 带 _v2 后缀，均暗示草稿/过渡状态。

影响 可读性差，后续维护者难以判断正式版本；若与旧口径并存易误用。

建议 口径稳定后统一命名规范，去掉 v 前缀、_新口径/_v2 后缀。

轻微「指标名」映射为 16 条 if-else 硬编码

L1-KFM日报.tmdl — 添加指标名 步骤

业务映射规则硬编码在 M 里，可维护性差。建议把映射规则移入「日报指标映射」Excel（新增「指标名」列），M 只做 join。

合理之处与总结建议

已完成的改进：
  • 映射表数据源由本地硬编码路径改为 SharePoint.Files（参数 SharePoint站点）。
  • 「年累计完成L1」口径修正：累计预测数 → 累计实际数（新增该列），消除重复计算，并排除「其他指标」。
  • 两个内联中间表聚合由 List.Average 改为 List.Max。
  • 「最近月份」过滤排除 null 与 0 值月份。
  • 「标准日期」改用 Date.FromText 按 yyyy.MM.dd 显式解析。
  • SAP BW 服务器/系统编号/客户端ID 参数化。
  • 映射表改为按 Sheet 名称取数（消除行索引钻取），SharePoint 读取合并为 3 步。
  • 月报事实表新增「指标类别」列（18→19 列），由月报指标映射 join 带入。
  • 「类别2」统一改名为「二级指标」，二级指标细分从「类别」改为「序号」驱动（月报序号 5/13/14/15/16，日报序号 2/3/4/5）。
  • 日报表回补「指标名称」「产品分类」两列（15→17 列），序号/环节序号/排序 类型统一为 int64。
  • 入选品位体系精简为 4 个「新口径」度量值：2 个入矿品位 + 2 个选冶回收率（含浸出/洗涤/修正系数）。
值得保留的设计： 兼容级别 1702 + DAX UDF 统一动态格式；「月份-筛选器」用「最近月份」文本标记并由 SameMonthPriorYear 解析；排序键「序号×10 + 铜钴次序」；月报起点留出 2025 全年以支持去年同期；回收率计算含修正系数（铜 0.995 / 钴 0.98）。

优先处理顺序

1修复 年累计完成L1_v2 语法错误（严重）——把 VAR 提到 SWITCH 之前，否则该度量值报错、关联视觉失效。
2修复日报「二级指标」复制粘贴错误（中等）——序号=2 的全铜分支条件由「全钴TCo」改为「全铜TCu」。
3核实「比计划」口径（中等）——确认月报比率 vs 日报差额的业务语义。
4统一新口径度量值命名（轻微）——稳定后清理 v 前缀与 _新口径/_v2 后缀。
